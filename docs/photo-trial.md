# Проверка распознавания фото

Реализован отдельный пробный поток: Telegram → GLM-4.6V-Flash → проверенный JSON.
БД не используется. Покупки, рецепты и другие возможности полного MVP пока не реализованы.

## Запуск

В корне проекта:

```powershell
uv sync --locked
uv run --locked python -m ingredia
```

В локальном .env нужны TELEGRAM__USER__TOKEN, TELEGRAM__USER__USERNAME и AI__ZAI__API_KEY.
Ключи не публикуйте и не добавляйте в Git.

По разрешению пользователя в текущем локальном .env установлен открытый пробный доступ:

```dotenv
TELEGRAM__TRIAL__OPEN_ACCESS=true
```

Для ограничения доступа установите false и укажите свои числовые Telegram ID:

```dotenv
TELEGRAM__TRIAL__OPEN_ACCESS=false
TELEGRAM__TRIAL__ALLOWED_USER_IDS=[123456789]
```

После изменения .env перезапустите процесс. Команда /id в личном чате показывает собственный ID.
В .env.example доступ по умолчанию закрыт; значение true включается явно.

Работает один процесс без reload и нескольких workers: для одного токена нужен один poller.
При уже настроенном webhook запуск прерывается; прототип не удаляет чужую настройку автоматически.
Проверка состояния: http://127.0.0.1:8000/health. Это состояние процесса, не проверка качества GLM.
Остановка в терминале — Ctrl+C.

## Проверка фото

1. Откройте @ingredia_helper_bot, отправьте /start.
2. Пришлите одну фотографию продуктов обычным фото, не документом.
3. Получите файл recognition-<номер сообщения>.json.
   Короткий JSON также появляется текстом в чате.

Пример структуры одной позиции:

```json
{
  "name": "Молоко",
  "visual_description": "Два пакета молока",
  "brand": null,
  "package_count": 2,
  "quantity_per_package": {
    "value": 1.0,
    "unit": "l",
    "evidence": "На пакете: 1 л"
  },
  "expiry_date": null,
  "expiry_evidence": null,
  "needs_clarification": false,
  "clarification_question": null
}
```

Корневой JSON содержит products и warnings. Количество указывается на одну упаковку,
package_count — число видимых упаковок; 2 × 1 л не превращается в 3 л.
Неизвестные значения остаются null. Неясное название сопровождается вопросом.
Вопрос пока только выводится: полноценный диалог уточнения не реализован.
Проверка схемы не доказывает фактическую правильность распознавания — проверьте результат сами.

Фото передаётся Z.ai, предварительно декодируется и пересохраняется без EXIF/метаданных.
JPEG/PNG до 5 МБ и 20 млн пикселей уменьшаются до 2048 пикселей по длинной стороне.
Оригинал и обработанное фото живут в памяти приложения; файлы на сервере не создаются.
Telegram хранит отправленное пользователем фото и ответ по своим правилам.
Удаление памяти приложения не означает удаления данных у Telegram или Z.ai.

## Границы прототипа

- Один вызов только выбранной бесплатной glm-4.6v-flash на фотографию.
  Платного fallback и автоматических повторов модели нет.
- Обработка последовательная, между фотографиями одного пользователя — пауза 15 секунд.
- Повторы сообщений отсеиваются в памяти процесса. После перезапуска история забывается;
  это не production-гарантия идемпотентности и не долговечная очередь.
- Фото в группе не обрабатываются. Фото как документ, голос и альбом как единый ввод не поддержаны.
  Каждый элемент альбома Telegram может доставить отдельным сообщением.
- При ошибке отправки результата распознавание не выполняется повторно автоматически.
- Сроки не рассчитываются по внешнему виду. Дата допустима только с читаемой маркировкой;
  модель всё равно может ошибиться. Свежесть и безопасность еды не подтверждаются.

## Что переиспользуется

- ingredia/recognition/models.py — схема результата на Pydantic.
- ingredia/recognition/media.py — ограничение размера и удаление метаданных.
- ingredia/recognition/service.py — контракт PhotoRecognizer и сервис пробной обработки.
- ingredia/adapters/zai/ — облачный адаптер, безопасные ошибки и проверка ответа.
- ingredia/adapters/telegram/ — Telegram-представление результата.
- ingredia/app.py — FastAPI и жизненный цикл клиентов/polling.

Для одного запроса достаточно HTTPX и Pydantic. Pydantic AI рассмотрен, но его агентный слой
сейчас не нужен: нет инструментов, планирования и диалога агента. Схема не зависит от SDK,
поэтому адаптер можно заменить на Pydantic AI позднее без переделки предметного результата.

## Проверки

```powershell
uv run --locked pytest
uv run --locked ruff check .
uv run --locked ruff format --check .
uv run --locked mypy ingredia
```

Автоматические тесты используют подставные HTTP/Telegram ответы и искусственные изображения.
Реальное качество GLM проверяется отдельно по фото пользователя.

Источники:
[aiogram polling](https://docs.aiogram.dev/en/latest/dispatcher/dispatcher.html),
[Z.ai API](https://docs.z.ai/api-reference/llm/chat-completion),
[Pydantic AI output](https://pydantic.dev/docs/ai/core-concepts/output/).

## Структура адаптеров и logging

В adapters/zai/ разделены модели API, HTTP-клиент, ошибки, проверка ответа и recognizer.
Промпт находится в adapters/zai/prompts/food_photo_v1.txt и загружается как ресурс пакета.
В adapters/telegram/ разделены модели сообщений, загрузка фото, presenter, handlers и router.
Сборка и закрытие клиентов — в ingredia/runtime.py, HTTP-маршруты — в ingredia/app.py.

Logging конфигурируется один раз в ingredia/logging_config.py. Модули используют get_logger.
Из .env можно задать LOGGING__LEVEL=INFO. Вывод включает UTC-время, уровень и имя модуля;
значения настроенных секретов маскируются, сырые фото и ответы модели не логируются.

До рефакторинга прошёл 31 pytest-тест. После рефакторинга проверены Ruff и mypy;
pytest и живые запросы к GLM не повторялись по указанию пользователя.
