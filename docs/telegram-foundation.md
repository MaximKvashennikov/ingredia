# Первая реализация Telegram MVP

## Что работает

- Личный Telegram-аккаунт с внутренним ID, /start, /menu, кабинет и главное меню.
- Личный холодильник с отдельными партиями и ручным вводом.
- /add Молоко | 2 | l | 2026-11-05 — покупка; /fridge 2 — вторая страница.
- Количество и срок можно оставить пустыми; неизвестные данные не выдумываются.
- Повтор одного сообщения не добавляет вторую покупку.
- Отдельный админ-бот с кнопочным меню: пользователи, поиск, заблокированные и помощь.
- Поиск по имени, точному Telegram ID или ID аккаунта; фильтры всех/активных/заблокированных.
- Карточка открывается кнопкой из списка; блокировка/разблокировка — кнопкой из карточки.
  Причина вводится отдельным сообщением, затем требуется подтверждение.
- «Назад» сохраняет поиск, фильтр и страницу; «Главное меню» отменяет незавершённый ввод.
- Команды /users, /block и /unblock остаются дополнительным способом управления.
- Изменение статуса требует кнопки подтверждения; доступны отмена, срок действия и защита
  от повтора. Устаревшая версия не перезаписывается. Статус и аудит сохраняются атомарно.
- Административный доступ только по доверенному числовому ID; пустой allowlist запрещает доступ.
  Администраторов нельзя блокировать через эти команды.
- Добавление покупок по фото или свободному тексту через выбранный AI-адаптер с читаемым
  предварительным списком.
- Подтверждение сохраняет весь список атомарно. Отмена, старые и чужие кнопки не меняют запасы.
- Новый распознанный список заменяет прежний; неясные продукты требуют нового уточнённого списка.
- Срок подтверждения — 30 минут. Черновики хранятся в БД и переживают перезапуск.
- В меню иконки, карточки разделены, единицы и даты отображаются по-русски.

Голос, сверка фотографии полки с запасами, персональные поправки, полное редактирование
партий и отмена изменения запасов пока не реализованы.
Просмотр истории аудита отдельным экраном пока не реализован.
Текстовые шаги и подтверждения админа живут в памяти, ограничены по времени;
после перезапуска старые кнопки не выполняют действия — откройте меню заново.
Полная административная спецификация ещё не закрыта.
Полные упаковочные атрибуты, расширение справочника сроков, outbox и отдельный worker —
следующие этапы.
Адресные уточнения отдельных позиций и частичное сохранение ещё не реализованы.
Для исправления отправьте полный уточнённый список новым сообщением.
Количество упаковок преобразуется в общий остаток; полные упаковочные атрибуты пока не хранятся.

## Запуск Docker

Локальный .env содержит секреты и доверенный ID администратора.
Секреты исключены из Git и образов. В .env.example только шаблоны; .env не перезаписывайте.

    docker compose up -d --build

Compose запускает PostgreSQL, одноразовую миграцию и приложение с двумя polling-задачами.
У каждого токена один consumer; параллельно локальный бот не запускать.
При ошибке проверки админ-токена пользовательский канал продолжает работать.

HTTP доступен на localhost:8000. /health отражает пользовательский polling,
/health/admin — административный. Это не проверка доступности AI и не постоянная проверка БД.
PostgreSQL опубликован только на loopback:5432 для локальной разработки.
Для сервера убрать публикацию БД или оставить loopback; публичного веб-интерфейса нет.

Остановка без удаления данных:

    docker compose stop

## Локальный Python

    docker compose up -d postgres
    uv sync --locked
    uv run --locked alembic upgrade head
    uv run --locked python -m ingredia

DATABASE__URL в .env указывает на локальный PostgreSQL. Compose использует внутренний адрес.
Без DATABASE__URL сохраняется режим фото-пробы; меню и админ-бот в нём не подключаются.

## Проверки

    uv run --locked pytest -q
    uv run --locked ruff check .
    uv run --locked ruff format --check .
    uv run --locked mypy ingredia

Два интеграционных теста PostgreSQL включаются через TEST_DATABASE_URL.
Используйте тестовую БД с разрешением создавать схемы: каждый тест создаёт случайную
test_<uuid> схему и удаляет только её. SQLite-проверки не заменяют PostgreSQL.
Telegram/GLM-вызовы в pytest подменены, квоты моделей не расходуются.
Ручная приёмка в Telegram выполняется отдельно от автоматизированного QA.

Выбор GLM/Qwen описан в [настройках провайдеров](ai-providers.md).

## Покупки, холодильник и рецепты — 2026-10-30

- Фото принимается как фотография Telegram или JPEG/PNG-файл. Ограничения размера сохраняются.
- Для Groq-фото используется JSON mode с локальной Pydantic-проверкой. Текстовый режим остаётся
  со строгой JSON Schema. На публичном фото воспроизведён отказ прежнего строгого vision-запроса;
  после изменения получен валидный список из шести видов продуктов.
- Срок с маркировки или из явного текста имеет приоритет. Для 14 поддержанных категорий есть
  справочные оценки; другие даты остаются неизвестными. Справочник не является обученной моделью.
- Перед сохранением показаны оценочные даты и условия: сегодняшняя свежая покупка, холодильник
  ≤4 °C и указанный вид продукта. Можно сохранить весь список без оценочных дат.
- Оценка хранится с правилом, длительностью, опорной датой, условиями и ссылкой на источник.
  Старые партии не получают новые даты автоматически.
- В холодильнике шесть кнопок продуктов на странице. Карточка открывает количество, дату,
  источник и условия; страницы и обновление редактируют текущее сообщение.
- После подтверждения покупок предлагается кнопка подбора рецептов. «Что приготовить» в меню
  запускает такой же подбор; облачный запрос не выполняется просто при просмотре холодильника.
- До трёх AI-рецептов содержат порции, количества и шаги. Наличие ингредиентов пересчитывает
  приложение: есть, не хватает, нужно проверить количество. Масло и соль не предполагаются.
- Истёкшие подтверждённые и оценочные сроки исключаются. Неизвестные сроки явно обозначены.
- Из карточки рецепт сохраняется в избранное. Список, открытие и удаление работают без новой
  генерации; содержание сохраняется снимком, доступность сверяется заново.
- Подбор пока ограничен 60 партиями, сопоставление названий консервативное: без морфологии
  и смысловых замен. Просмотр избранного этим лимитом не ограничивается.
- Подбор и просмотр рецептов не меняют остатки. «Закончилось», временные исключения и сверка
  фотографии полки с запасами остаются следующими задачами.

Рецепты подключены через RecipeGenerator; Groq и Z.ai реализуют этот порт отдельно.
Фото/текст и рецепты имеют отдельные паузы между запросами: покупка не блокирует следующий подбор.
Обычный QA использует fake adapters; внешний пробный запрос не является ручной приёмкой Telegram.

Источник справочных длительностей: [Nebraska Extension][storage].
Используется нижняя граница диапазона, где источник даёт диапазон.
Это ориентир для планирования, не оценка текущей свежести.

[storage]: https://food.unl.edu/free-resource/food-storage/

## Где смотреть диагностику

    docker compose logs -f --tail 100 app

Для фото записываются факт получения, размер подготовленного изображения, категория отказа
или число продуктов и предупреждений. Для Groq дополнительно HTTP-статус и известный код ошибки.
Неизвестный код заменяется на other. Тела ответов провайдера, фотографии, текст и секреты
в этих записях отсутствуют. Прежний отказ конкретного фото восстановить нельзя:
до исправления обработчик покупок его не записывал.

## Автоочистка и настройки — 2026-10-31

Партии физически удаляются при просрочке больше 30 календарных дней, включая оценочные даты.
Ровно 30 дней и неизвестный срок сохраняются. Календарь — Europe/Moscow.
Очистка выполняется при старте, раз в час и перед чтением собственных запасов.
Избранное, снимки рецептов и аккаунты не удаляются.
Остаётся только ключ события без атрибутов продукта, чтобы повтор не восстанавливал партию.
Сбой фоновой очистки логируется классом ошибки, повтор — через минуту.
При подборе остатки не списываются; автоочистка — отдельное исключение.

Settings разделён по компонентам. Новые имена, значения ключей локально сохранены:

    TELEGRAM__USER__TOKEN=...
    TELEGRAM__ADMIN__TOKEN=...
    TELEGRAM__ADMIN__USER_IDS=[123]
    TELEGRAM__TRIAL__OPEN_ACCESS=true
    AI__PROVIDER=groq
    AI__GROQ__API_KEY=...
    AI__ZAI__API_KEY=...
    DATABASE__URL=...
    LOGGING__LEVEL=INFO

Старые плоские имена заменены. POSTGRES_PASSWORD остаётся переменной образа PostgreSQL.
TEST_DATABASE_URL — переменная pytest, не поле Settings.
