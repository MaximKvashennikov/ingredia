# Переключение распознавания: GLM и Qwen

## Как устроено

Прикладной поток использует PhotoRecognizer, TextRecognizer и RecipeGenerator.
Telegram, подтверждение покупок и PostgreSQL не выбирают облачный API.
Фабрика в ingredia/providers.py создаёт адаптеры по AI__PROVIDER.

- zai: сохранённый Z.ai — glm-4.6v-flash для фото, glm-4.7-flash для текста.
- groq: отдельные адаптеры Groq — qwen/qwen3.8-27b для фото, текста и рецептов.
- Общие структуры сообщений, ограниченный HTTP-транспорт и проверка ответов находятся
  в adapters/chat_completions. Настройки запросов и ошибки провайдеров остаются раздельными.
- Промпты вынесены в recognition/prompts. GLM получает прежние инструкции и параметры.
- Qwen использует instruct-режим. Фото запрашивается в JSON mode со схемой в промпте:
  строгий vision-запрос воспроизвёл HTTP 400 / json_validate_failed. Текст и рецепты
  используют строгую JSON Schema без дублирования схемы в промпте.
  Все результаты повторно проверяются локальным Pydantic.
- Никакого автоматического fallback, выбора другой модели или пополнения баланса нет.
  На один ввод выполняется один запрос к выбранному сервису.
- Ключи обоих провайдеров имеют SecretStr и включены в маскирование логов.

## Настройки

GLM:

    AI__PROVIDER=zai
    AI__ZAI__API_KEY=<локальный ключ Z.ai>

Qwen:

    AI__PROVIDER=groq
    AI__GROQ__API_KEY=<локальный ключ Groq>

Нужен только ключ выбранного провайдера. Ключ второго можно оставить в .env для возврата.
Отсутствующий или пустой ключ выбранного провайдера вызывает явную ошибку конфигурации
до подключения Telegram. Опечатка в AI__PROVIDER тоже не приводит к молчаливой замене.

После изменения .env:

    docker compose up -d --build

Перезапуск прерывает незавершённые запросы модели; подтверждаемые покупки остаются в PostgreSQL.

## Нулевой бюджет

У Groq необходимо использовать Free-план без включения платного Developer billing.
Сам адаптер не умеет определять тариф аккаунта; один и тот же model ID может оплачиваться,
если владелец аккаунта включил платный тариф. Код не подключает оплату и не увеличивает квоты.
Квоты и доступность зависят от аккаунта и провайдера. Окончание квоты даёт понятный отказ,
а не перевод на платную модель.

## Фактический статус на 2026-10-30

После отказа signup_blocked пользователь предоставил рабочий ключ Groq.
Ключ сохранён только в локальном .env; активирован AI__PROVIDER=groq.
GET /openai/v1/models вернул HTTP 200 и подтвердил доступность qwen/qwen3.8-27b.
Это проверка авторизации и каталога, а не генерация или проверка качества распознавания.

Приложение пересоздано через Docker Compose. Оба health endpoint вернули ok;
логи запуска подтвердили provider=groq. GLM и его ключ сохранены для явного возврата.
Тариф аккаунта и фактический остаток квот не проверены. Код не включает платный Developer-план
и не выполняет платный fallback. На публичном фото проверен транспорт и валидный список;
качество на пользовательских покупках требует ручной приёмки.
