# Design

PhotoRecognizer принимает PreparedPhoto и возвращает прежний PhotoRecognition.
Один выбранный vision-адаптер определяет тип изображения и извлекает позиции одним запросом.
Общий purchase_photo_v2.txt загружается обоими провайдерами через нейтральный prompt loader.

Чек — недоверенные данные. Не извлекаются реквизиты, QR, итоги, скидки и непищевые товары.
Цена не является количеством, дата чека не является сроком. Весовая строка хранит общий вес
без повторного умножения на упаковки. Справочный срок рассчитывается отдельно приложением,
с явно показанным допущением сегодняшней свежей покупки и возможностью отказаться от оценок.

Читаемость и смысловые сокращения определяет облачная модель, структура проверяется Pydantic.
Распознавание реальных чеков требует ручной приёмки. Ограничение — 20 продуктов в одном вводе;
вместо молчаливого обрезания промпт запрашивает части чека. Предупреждения не теряются даже
при пустом результате. Нечёткая позиция блокирует текущее общее подтверждение до исправления;
адресное уточнение и частичное сохранение остаются незавершёнными задачами MVP.

Запрос холодильника сортирует по наличию даты, дате, имени и ID до OFFSET/LIMIT.
Обе даты — подтверждённая и оценочная — участвуют в сортировке. Уже просроченные, но ещё
не удалённые партии идут перед будущими и отмечаются предупреждением.
Шесть кнопок, точный счётчик, возврат и редактирование страницы сохраняются.

Автоматические проверки используют fake Bot API и cloud responses; они проверяют контракт
и движение данных, а не качество OCR. Docker на момент проверки не запущен.
