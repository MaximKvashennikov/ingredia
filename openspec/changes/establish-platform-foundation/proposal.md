# Proposal

## Why

ingredia начинается с пустой папки и заданного технологического стека. До разработки нужно
определить общие контракты подключения ботов, безопасность и пользовательские состояния, чтобы
будущие провайдеры не диктовали устройство всего приложения.

Статус: черновик для обсуждения. Пользователь разрешил подготовку спецификаций; реализация исключена
из текущего запроса. Продукт — виртуальный холодильник с Telegram, описанный в
`docs/product-brief.md` и change `define-fridge-mvp` . ВК отложен.

## What Changes

- Предлагается общий жизненный цикл подключения бота и контракт возможностей провайдера.
- Определяются проверка доступа, защита секретов, ограничения входных событий и безопасные отказы.
- Предлагаются UX-требования к управлению подключениями и доступным состояниям интерфейса.
- В design и tasks фиксируются FastAPI, Telegram, uv, QA через pytest и последовательность
  будущих работ.
- PostgreSQL принимается основной БД; общий версионируемый API учитывает будущий Android-клиент, без
  реализации мобильного приложения сейчас.
- Docker Compose планируется для локального запуска и первого размещения на сервере.

Вне границ этого общего change: предметные фичи ingredia и распознавание (см. `define-fridge-mvp` ),
протокольные детали Telegram, конкретная система входа, выбор сервера и реализация. Паттерн адаптера
сохраняет возможность будущего ВК.

## Capabilities

### New Capabilities

- `bot-connections` : подключение и отключение ботов, возможности, обработка повторов и ошибок
  доставки.
- `platform-security`: доступ к ресурсам, секреты, доверие к событиям, аудит и ограничения ресурсов.
- `connection-management-ux`: понятный и доступный интерфейс жизненного цикла подключения.
- `client-api` : общий контракт данных и операций для серверных операций и будущих клиентов,
  независимая
  идентичность и совместимость версий.
- `container-deployment` : воспроизводимый локальный запуск и первое серверное развёртывание с
  сохранением данных и защитой секретов.

### Modified Capabilities

Нет: существующих реализованных спецификаций нет.

## Impact

Будущие компоненты: HTTP API, два Telegram-бота, обработчик событий, PostgreSQL для
подключений/операций и
провайдерские адаптеры. Контейнерный запуск через Docker Compose подтверждён; версия БД, серверная
среда, резервное копирование, хранение медиа и механизм входа уточняются перед соответствующей
фазой.

Предложения этого change не объявляются реализованными и не переносятся в базовые specs.
Проверяемость обеспечивается сценариями требований и планом pytest/ручной UX-приёмки в design.
