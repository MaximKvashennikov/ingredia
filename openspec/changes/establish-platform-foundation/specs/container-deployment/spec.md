# Container deployment

## Purpose

Воспроизводимый контейнерный запуск ingredia локально и при первом размещении на сервере без потери
пользовательских данных и раскрытия секретов.

## ADDED Requirements

### Requirement: Local container startup

Система SHALL предоставлять документированный запуск через Docker Compose для API, worker,
пользовательского и административного ботов
и PostgreSQL в локальном окружении.

#### Scenario: Clean local startup
- **WHEN** разработчик запускает проект по документации из чистого checkout с заданными локальными
  секретами
- **THEN** сервисы собираются и запускаются, API готов и оба Telegram-бота подключены, а PostgreSQL
  готов принимать
  подключения.

#### Scenario: Missing required configuration
- **WHEN** обязательная настройка или секрет отсутствует
- **THEN** зависимый сервис сообщает об ошибке конфигурации без раскрытия значения секрета.

### Requirement: First server deployment

Система SHALL поддерживать развёртывание тех же версий образов через Docker Compose на одном сервере
с отдельной серверной конфигурацией.

#### Scenario: Server release
- **WHEN** оператор применяет описанную серверную конфигурацию и запускает выбранную версию
- **THEN** оба бота доступны через Telegram; API публикуется только при необходимости транспорта,
  PostgreSQL и worker не публикуются напрямую.

#### Scenario: Deployment configuration check
- **WHEN** оператор проверяет конфигурацию перед запуском
- **THEN** ошибки структуры или отсутствующих обязательных параметров обнаруживаются до
  развёртывания.

### Requirement: Persistent data and recovery

Система SHALL сохранять данные PostgreSQL вне эфемерной файловой системы контейнера и предоставлять
документированную процедуру резервного копирования и восстановления.

#### Scenario: Container recreation
- **WHEN** контейнер PostgreSQL пересоздаётся без удаления постоянного хранилища
- **THEN** ранее подтверждённые данные пользователя остаются доступны.

#### Scenario: Restore exercise
- **WHEN** оператор восстанавливает тестовую копию в отдельном окружении
- **THEN** согласованные данные доступны, а результат проверки восстановления документирован.

### Requirement: Protected deployment secrets

Система SHALL получать секреты во время запуска, не включая их в образы, репозиторий или публичный
вывод конфигурации и диагностики.

#### Scenario: Image inspection
- **WHEN** проверяются собранные образы и отслеживаемые файлы проекта
- **THEN** Telegram-токен, пароль БД и другие рабочие секреты там отсутствуют.

#### Scenario: Service failure
- **WHEN** сервис завершается из-за ошибки настройки или внешней зависимости
- **THEN** диагностика позволяет определить отказ без раскрытия секретов.
