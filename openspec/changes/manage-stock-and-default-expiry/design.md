# Design

## Удаление

StockRemovalService использует общий active_account и блокировку owner → batch.
План содержит только ID и версии партий, владельца, mode и срок действия 10 минут.
Новый план отменяет предыдущий pending-план владельца.
Для очистки пользователь видит число партий и подтверждение/отмену.
Одна партия удаляется напрямую через delete_one после нажатия ❌; владелец и версия
проверяются в транзакции, повтор не возвращает продукт. Старые callback без версии
поддерживаются с обязательной проверкой владельца.

Для удаления одной партии сравнивается только она. Для очистки сравнивается весь набор:
новая покупка после открытия подтверждения вызывает Conflict вместо удаления невидимых данных.
Списание и минимальные RemovedStockEvent атомарны; повтор сообщения не возвращает продукт.
Пакеты по 500 строк выполняются внутри одной транзакции.
Ни аккаунты, ни Recipe/Favorites не удаляются. При переходе назад страница ограничивается
актуальным числом продуктов.

## Оценки

expiry_v2.json содержит 26 правил; целые фразы сопоставляются без учёта регистра, пунктуации,
бренда и фасовки. Исключения не дают применять правило сырого продукта к копчёному/готовому.
Самая конкретная подходящая фраза имеет приоритет.

Явная дата не меняется. Новая партия без даты получает оценку при записи.
У уже сохранённых пустых unknown-дат оценка заполняется при чтении один раз, под owner lock.
Для новых партий опора — added_on. Если дата старой покупки неизвестна, это явно сохраняется
в условиях; отсчёт идёт от даты оценки, не объявляя продукт свежекупленным.
Изменение даты повышает версию партии и делает прежнее подтверждение удаления устаревшим.

Если правило отсутствует, дата остаётся пустой с источником unavailable.
Политика «проверить завтра» отменена: она не основана на сроке хранения продукта.
Для известных категорий оценка подписывается «Примерно до», точная дата — «Годен до».
Без правила — «Срок не рассчитан»; ручное заполнение не требуется.
Явный отказ declined не переопределяется.

Старые review-записи нормализуются fill_missing_expiry под блокировкой владельца до сортировки
и очистки. При отсутствии правила дата и метаданные очищаются, версия повышается один раз.
Unavailable не попадает в повторное заполнение. Изменение версии защищает от старых кнопок.
Подтверждение старого purchase draft отбрасывает review-оценку перед сохранением партии.
Новая миграция схемы не нужна: дата уже nullable, источник хранится строкой.

## Вертикальный список

Таблица InputRichBlockTable заменена на InputRichBlockParagraph: минимальная ширина её колонок
вызывала горизонтальную прокрутку даже после сокращения названий.
В каждом блоке четыре строки: название-ссылка, количество, срок словами и «Удалить ❌».
Текст переносится средствами клиента Telegram; фиксированных колонок и таблицы больше нет.
Подпись названия ограничена 18 символами с «…», полное имя доступно в карточке.
Число продуктов на странице, сортировка и нижняя клавиатура сохраняются.

Действия используют link-style RichTextButton в native rich-сообщении, без Mini App и React.
Для отправки используется sendRichMessage, для обновления editMessageText с rich_message.
Названия передаются обычными rich-text строками с выключенным entity detection.
HTML полной карточки сохраняет экранирование пользовательских строк.

## Проверка

Pytest использует fake Telegram/AI и изолированные схемы PostgreSQL.
Проверяются вертикальные блоки без таблицы, явные подписи сроков, действия и полная карточка,
неизвестная категория, обработка старых review-записей и pending drafts, изоляция владельцев
и отсутствие повторного изменения версий. Сохранены проверки отмены, доступа, повторов, TTL,
конкуренции, отката удаления и больших запасов.
Ревью выполняется самостоятельно; реальный клиентский вид принимает пользователь в Telegram.
