# Design

## Context

Существуют PhotoRecognizer и TextRecognizer; прежний composition root создавал только Z.ai.
Пользователь выбрал Qwen через Groq, но получил signup_blocked и пока не имеет ключа.

## Decisions

AI__PROVIDER допускает только zai и groq. Значение по умолчанию zai сохраняет совместимость.
Фабрика получает Settings и общий HTTPX client, возвращая два типизированных порта.
Ветвление находится только в composition root; Telegram не импортирует SDK провайдера.

Z.ai сохранён с прежними моделями, thinking, параметрами и числовыми business-кодами.
Groq использует фиксированный qwen/qwen3.8-27b, reasoning_effort=none и JSON Schema.
Грубая структура контролируется API; исходные ограничения и согласованность проверяются Pydantic.
Общая схема не означает поддержку всех JSON Schema-ограничений на стороне провайдера.

HTTP-транспорт ограничивает тело, время, редиректы и выдаёт безопасные ошибки.
Он не повторяет запросы и не выбирает модели. Groq не импортирует Z.ai.
Промпты провайдеронезависимы; схема у Groq передаётся только через response_format.
Отсутствующий ключ останавливает запуск до сетевого подключения Telegram.

## Risks / Trade-offs

- Ключ API не сообщает приложению тариф Groq; Free-план выбирает владелец аккаунта.
- Регистрация, региональный доступ и квоты контролируются внешним провайдером.
- Контрактные fake-тесты не подтверждают качество реальных фото.
- Пока ключа нет, работающий GLM остаётся активным; автоматически обходить отказ регистрации нельзя.

## Validation

Pytest для обоих портов, выбора ключа, отсутствия fallback, HTTP-ошибок, таймаута,
редиректов, границ ответа и локальной проверки схем. Все существующие GLM-тесты сохраняются.
Реальное подключение и ручная проверка остаются отдельным этапом после появления ключа.


## Подключение активировано

Рабочий ключ получен позднее и хранится только в .env. Каталог Groq подтвердил выбранную модель.
Активирован AI__PROVIDER=groq; оба бота готовы. Запросы генерации в рамках активации не выполнялись.
Первоначальная внешняя ошибка регистрации не препятствует использованию предоставленного ключа.

## Исправление vision-режима — 2026-10-30

Внешняя проверка на публичном фото OpenCV воспроизвела HTTP 400 / json_validate_failed.
Поэтому фото заранее использует JSON Object Mode со схемой в промпте и локальной валидацией.
Текст и рецепты используют строгую JSON Schema. Повторов, выбора другой модели и fallback нет.
После изменения публичный снимок вернул валидные наблюдения шести видов продуктов;
это не доказательство качества на всех пользовательских фото.
