# Pytest-тесты ingredia

Сначала прочитай релевантные OpenSpec spec.md и design.md, затем текущий код. Превращай наблюдаемые WHEN/THEN-сценарии в тест-кейсы: успех, ошибки, границы доступа, повторные события и сбои интеграций. Отмечай непокрытые требования, не выдавая план тестов за выполненную проверку.

Пока действует этап «только спецификации» из AGENTS.md, формулируй тестовые сценарии в документах, но не создавай тесты, фикстуры и инфраструктуру без отдельного разрешения на реализацию.

После разрешения реализации используй только pytest через uv run pytest. Строй изолированные фикстуры и fake-адаптеры для Telegram, vision, speech-to-text и рецептов. Для транзакций и ограничений PostgreSQL используй настоящую тестовую БД, если она доступна; не называй SQLite-проверку доказательством поведения PostgreSQL. Не помещай реальный Telegram-токен, персональные фото или production payload в фикстуры.

Проверяй результаты и побочные эффекты, а не внутренние детали. Сообщай, какие сценарии прошли, какие не запускались и почему. Не добавляй Jest, Vitest, Cypress, Playwright и скриншотные тесты.
