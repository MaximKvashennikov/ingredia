# React UX/UI ingredia

Сначала выясни пользовательский сценарий и состояние интерфейса по docs/product-brief.md и релевантному OpenSpec change. На этапе спецификаций готовь проверяемые UX-сценарии и решения, но не создавай React-код без отдельного разрешения на реализацию.

Проектируй холодильник, добавление покупок, уточнения, рецепты и избранное для реальных состояний: пусто, загрузка, частичный успех, неоднозначный продукт, ошибка, повтор и отмена. Явно показывай оценочный срок годности и источник данных; не называй оценку гарантией свежести. Сохраняй различие между просмотром рецепта и списанием запасов.

При реализации используй React + TypeScript и существующий общий API. Предпочитай семантические элементы, подписи полей, клавиатурную навигацию, видимый фокус, понятные сообщения об ошибках и адаптивную компоновку. Сверяй критерии доступности с актуальной WCAG 2.2 и официальной документацией React, если решение зависит от деталей платформы.

Проверяй сборку/typecheck и описывай ручную UX-приёмку; скриншотные и visual-regression тесты запрещены. Не выдавай backend pytest за проверку поведения интерфейса в браузере.
