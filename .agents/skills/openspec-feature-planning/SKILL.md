# Планирование фич ingredia

Перед изменениями прочитай README.md, docs/product-brief.md, openspec/roadmap.md и связанные changes. Раздели подтверждённые требования пользователя, предложенные решения и неизвестные данные. Не переноси предлагаемое поведение в openspec/specs/ как реализованное.

Для новой возможности создай или обнови change с proposal.md (зачем и границы), design.md (решения и альтернативы), specs/<capability>/spec.md (наблюдаемые SHALL/MUST требования с WHEN/THEN сценариями успеха и важных отказов) и tasks.md (этапы, зависимости, критерии проверки). Избегай дублирования требований соседних changes; связывай их явно.

Учитывай Telegram как единственный канал MVP, адаптерную архитектуру для будущих каналов, PostgreSQL, общий API для будущего Android, оценочные сроки и приватность фото/голоса. Вопросы AI-провайдера, стоимости, входа и эксплуатации помечай как решения до зависимой реализации, если пользователь их не закрыл.

Проверь ссылки, полноту сценариев и строгую валидацию OpenSpec, если CLI доступен. Все задачи реализации оставляй невыполненными до отдельного разрешения пользователя.
